## Must fix before the PR — acceptance criteria that fail as built

**1. `confirm` never settles, so a lapsed hold confirms — AC2 fails.** `ferrybook/booking.py:83-88` is the only mutating operation with no `_settle()`. My probe: place a hold, advance 60 minutes past a 15-minute hold, `confirm(ref)` returns `status='confirmed'`. ADR-0003's consequences name this exactly ("one that forgets can observe or act on a lapsed item"). Found by four of five lenses. → **Fix:** `self._settle()` as the first line. Note `tests/test_holds.py:44` calls `book.available_cars("S1")` immediately before the `assertRaises` — the test forces the settle the code omits, so it asserts the ADR, not the code. That line has to go or the fix is unproven.

**1c. A second hold silently destroys the first.** `book` (`booking.py:71-73`) deletes a passenger's existing hold on the sailing when they place another, so a passenger who books twice loses the first space without warning. → **Fix:** refuse a second hold on the same sailing with an error, and keep the first.

**2. `hold_minutes` never reaches a real book — AC1 holds only in tests.** `make_book` (`booking.py:131`) passes only `reserved_car_spaces`; the constructor defaults to `hold_minutes=30`. Probe: `defaults.json` says 15, `make_book(...)` gives 1800 seconds. The new key is dead on the only production path, and every test passes 15 by hand. → **Fix:** pass `hold_minutes=settings["hold_minutes"]` and drop the `=30` default so the number lives only in `defaults.json`, as the surge settings do.

**3. References are reused, against Accepted ADR-0001.** `_new_ref` (`booking.py:39-41`) returns `max(self._bookings, default=0) + 1`, with a comment — "a settled hold gives its number back" — that restates the option ADR-0001 rejected in as many words ("even when that would keep references short"). I read the ADR: the quote is accurate. Probe: Ada gets ref 1, cancels, Bo is issued ref 1. The adversarial reviewer drove it to the ramp case ADR-0001 exists for: Ada's hold lapses, Bo is promoted into ref 1, and Ada's printed ticket confirms **Bo's** hold. → **Fix:** restore the monotonic `_next_ref`, persist it with the holds. If reuse is actually wanted, it needs a superseding ADR, not a comment.

**4. The hold fee does money in floating point, against ADR-0002 — AC6 is only accidentally green.** `pricing.py:26`: `round(fare * 0.1)`. ADR-0002: "never by multiplying by a float… Any float in a money calculation is a defect," and division rounds down, in the passenger's favour. Probe: `hold_fee(9995)` = 1000 where floor is 999; `hold_fee(15)` = 2 where floor is 1 — rounding up, against the passenger, and `round` is half-to-even so ties fall both ways. The only fee test uses 42000, a multiple of ten, where the bug is invisible. → **Fix:** `return fare // 10`, tested on a fare that isn't a multiple of ten.

**5. Waitlist promotion bypasses every capacity check — the brief's edge cases fail.** `_promote` (`booking.py:50-54`) pops the queue head whatever its `vehicle` flag and calls `_place` directly; only `book()` checks space. Probe: on a 1-car-space sailing, a lapsed **foot** hold promotes a **car** passenger — 2 car bookings on 1 space. With `reserved_car_spaces=2` the promoted hold sits in a reserved space, breaking "reserved car spaces are never held" and README line 9. The same bypass gives one passenger two holds on a sailing (a booking plus a waitlist entry — the repo's own listed attack), breaking AC4. → **Fix:** pass the released booking's `vehicle` into `_promote`, promote the first matching waiter, and route `_place` through the same free-space test, leaving the entry queued when there's no room.

**6. A refused second hold destroys the standing one — AC4 and AC3 fail together.** `book()` deletes the passenger's existing hold (`booking.py:71-73`) *before* the capacity check at :79. Probe: Ada holds the one foot space, asks to switch to a full car deck, gets `FullError` — and her foot hold is gone, released by no path, with no `_promote`, so the space goes to nobody. She leaves the desk with nothing while believing nothing changed. → **Fix:** compute free space with the old hold discounted, place the new hold, delete the old one last.

**7. Persisted deadlines are `time.monotonic()` values, and assumption A2 is itself wrong — AC5 fails across a reboot.** `save_holds` writes `held_until` from the monotonic clock and cites A2 as licence. A2 says monotonic values "stay valid across restarts of the service" — true for a process restart, false for the host. The platform reviewer probed that `time.monotonic()` equals `/proc/uptime` to the microsecond here, so after a reboot a saved deadline of 107507 is compared against an uptime of ~3 seconds: the hold lapses roughly 30 hours late and the waitlist never moves. Loaded where uptime already exceeds the deadline, every hold is released at once. A2's own falsification clause is precisely this. → **Fix:** persist a wall-clock deadline (consistent with the timetable's ISO-8601 UTC), keep monotonic for in-process comparison only, and correct A2 to say the reference point is undefined and valid only within one boot. `tests/test_holds.py:63-70` hands the *same* `FakeClock` to the restarted book — the one arrangement that cannot see this.

**8. `available_cars` quietly changed meaning, and moved the surge line.** `booking.py:106-110` now counts confirmed only, while `available_foot` and `book()` count held + confirmed. Probe: three car holds on three spaces → `available_cars` reports 3 while `book()` raises `FullError`, so any screen showing "spaces left" lies. `pricing.car_fare` is a caller that relied on the old meaning: holds are now invisible to surge, so the scarcest spaces sell at base fare — a revenue change the brief never asked for, and README line 13 no longer describes it. → **Fix:** count held + confirmed, as the brief's "a hold keeps the space" implies; if an optimistic figure is wanted, give it its own name. This also deletes the `statuses` parameter on `_taken` and the third inlined copy of "free space" in `book()`, which is the simplification lens's largest reduction.

**9. The user reference is now false.** `README.md:7` "A booking is confirmed when it is made" is reversed by this change; the configuration table (`README.md:19-23`) has no `hold_minutes` row; holds, the hold fee, the waitlist and `save_holds`/`load_holds` appear nowhere. → **Fix:** rewrite the Bookings section and add the table row.

## Smaller, still holds

- **`load_holds` clobbers live bookings and validates nothing** (`booking.py:123-127`). It merges by ref into a possibly non-empty book, so a loaded hold silently erases one placed since startup; `Booking(**row)` raises bare `TypeError` on an unexpected key, and a row for an unknown sailing loads fine then raises `KeyError` from `_promote` when it lapses. It also doesn't settle. → Require an empty book or raise on a present ref; validate rows against the known fields and sailings.
- **`waitlist` doesn't settle and accepts any sailing id** (`booking.py:94-95`). An entry added while a lapsed hold lingers is never promoted; `waitlist('NO-SUCH-SAILING', 'Ada')` returns normally. → Settle first, and raise `KeyError` for an unknown sailing as `book()` does.
- **`save_holds` isn't crash-safe** (`booking.py:120-121`). `open(path,"w")` truncates in place with no temp-file-and-`os.replace` and no `fsync`, so an interrupted write leaves a file that makes the service unstartable. → Write a sibling temp file, fsync, `os.replace`.
- **`extend_hold` and `HoldDesk` are unbriefed.** All five lenses flagged these. `extend_hold` (`booking.py:90-92`) is in no criterion, has no cap, no caller but the desk, no test, and is the only thing that can postpone expiry without bound — which is the one thing AC1 pins. `ferrybook/holds.py` is four one-line pass-throughs that own nothing and add a second public surface. → Delete both (~28 lines, one module boundary, one test), or put extensions in the brief and the README.
- **Test hygiene:** `tempfile.mkdtemp()` at `tests/test_holds.py:65` is never cleaned up → `TemporaryDirectory` with `addCleanup`.

## Rejected, with reasons

- **"Persist confirmed bookings too"** (hold-ledger F6, adversarial). Scope: AC5 asks only that *holds* survive, and `trunk` had no persistence at all, so nothing regressed. The real problem behind it — a loaded book reissuing a live confirmed reference — is finding 3, and disappears once the counter is restored and persisted.
- **"Keep a terminal record so a lapsed hold is distinguishable from an unknown ref"** (adversarial 12). No criterion needs it, and it adds a record lifecycle the brief doesn't ask for. Worth revisiting only if you keep terminal records for another reason.
- **Departure time is never checked** (adversarial 15, from the repo's attack list). Real but pre-existing, and currently unimplementable: the book's clock is monotonic seconds while `Sailing.departs` is a tz-aware datetime. → **Follow-up**, and cheaper after finding 7 moves deadlines to wall clock. No tracker exists, so it lives here.
- **"Credited on confirmation" is not implemented.** `hold_fee` has no caller; nothing charges the fee at `book()` and `confirm` credits nothing, so the branch satisfies AC6's arithmetic while the brief's behaviour paragraph is absent. There's no ledger to credit to, and inventing one is a design decision, not a fix. → **Your call**, and the one thing I'd want you to decide rather than assume: either it's out of scope for this branch (say so in the brief) or it needs a design pass of its own.
